# A 60-second demo

Run `npm ci`, then `npm run demo`. Open **http://127.0.0.1:4202**. No AWS account or credentials are needed. The yellow banner says **DEMO MODE: local only, no real sign-in**.

1. **0-10 seconds:** Choose **Use Avery Rowan**. Show Mesa Sprout Landscaping's team workspace, with Jobs 2026, Estimates, Site photos, Signed agreements, and Invoices. Crew handbook.pdf and Plant care sheet.pdf sit at the top level.
2. **10-20 seconds:** Open Jobs 2026 and preview October crew plan.txt, then open a customer folder for job notes and a materials CSV. Open Site photos in grid view and preview a matching before/after pair of yard sketches showing gravel, plants, and a patio. All six PNGs and all paperwork are generated by code, with no downloaded media.
3. **20-30 seconds:** Choose **Use Jordan Vale** in the banner. The same team files are visible with uploader attribution. Select two files and use Move to folder. Trash a file and restore it from Deleted files. Shared links contains an active sign-in-required link to the crew plan.
4. **30-45 seconds:** Switch back to Avery and open Documents. One agreement is waiting for Riley Fern; another is already complete. Use **Open sample agreement** in the demo banner to see the customer view in a new tab. Check consent, type a synthetic name, draw a signature, and select Sign.
5. **45-60 seconds:** Download the resulting two-page PDF. Show the appended signatures page and **Made with PickBits File Share** line. Open `.demo-data/outbox/` to see captured `.eml` messages, including the signed attachment sent to both parties. No email has left your machine.

All people, businesses, job details, signatures, and contact details are invented. Mesa, Arizona is a real city used for context. No real customer material or operator deployment identifiers are included. Email addresses use example.com, street addresses are invented, and the office phone uses the reserved 555-01xx range. The yard illustrations are fictional layouts, not real properties. This disclosure belongs in the demo banner and project documentation; the business paperwork reads like customer-facing documents.

A fresh seed has 20 files (19 active and one in Deleted files), seven folders including two customer folders, three estimates, two invoices, six yard PNGs, and a signed agreement. Avery and Jordan both appear as uploaders; file modification dates span the last eight weeks. Two files are starred. One active file share requires sign-in, and Documents contains one agreement awaiting signature and one signed agreement. Signing times and link expiry use the actual time the demo is seeded.

The demo stores bytes in `.demo-data/objects/`, metadata in `.demo-data/metadata.json`, and initial link locations in `.demo-data/demo.json`. Changes persist across restarts. Links expire normally, so reset an old demo before recording: stop it, then run `npm run demo -- --reset`. Reset deletes only that local demo directory and reseeds it. Relinking an agreement invalidates the original banner link until reset; the Documents view exposes the new link.

The demo supports the file/document workflows through the same API as production. Its sign-in and invitations are simulated, and its local table implements only the application's used operations. Owner/member MFA enforcement is covered by unit tests; the two demo identities have preverified factors so a recording needs no authenticator. A real AWS deployment still needs separate browser login and email-delivery validation.

Press Ctrl+C to stop. Do not expose the demo through a tunnel, proxy, or non-loopback listener. Use only synthetic files when recording.
